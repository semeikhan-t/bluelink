# План: паритет редактора BlueLink с Obsidian 1.14.5

> Источник требований: разбор агента ([сравнение с Obsidian](a8d0d8ea-31c6-4165-bf7b-4afd5f254422)), Evidence `ev_5db32f3878572510777237ce8ad61084c93ee2cdf233877d26cd0e77a1733fbe`, синтаксис из `sandbox/Formatting/` в `obsidian.asar` (SHA-256 `3a349274…491780`).
>
> Область: поведение **редактора** (набор, live-preview, команды `editor:*` / `markdown:*`). Команды `workspace:*` (панели, PDF, новое окно) — вне этого плана.
>
> Принцип этапов: один узкий результат на этап, проверяемый вручную или одним маленьким unit-тестом. Не смешивать «модель данных» и «меню» в одном этапе без нужды.

## 0. База и договорённости

### Уже закрыто (не делать заново)

Live-редактор; жирный / курсив / код / зачёркивание / `==`; заголовки; цитата; списки; таблица (часть операций); callout как карточка; сноска `[^N]`; математика; блок кода с простой подсветкой; `[[wiki]]` по имени файла; клик по `#тегу`; переход по `#заголовку` и `^блоку`; картинки + ресайз; свойства как пары ключ/значение; оглавление с переименованием; поиск/замена буквальной строки.

### Модули, которых касается план

| Модуль | Роль |
|--------|------|
| `crates/bluelink_ui/src/editor.rs` | Live-строки, ввод, команды |
| `crates/bluelink_ui/src/editor_menu.rs` | Контекстное / Edit-меню |
| `crates/bluelink_ui/src/preview.rs` | Разбор/отрисовка строк, callout |
| `crates/bluelink_ui/src/fold.rs` | Сессионные складки заголовков/отступов |
| `crates/bluelink_ui/src/footnote.rs` | Поле определения сноски |
| `crates/bluelink_ui/src/table.rs` | Таблица |
| `crates/bluelink_ui/src/properties_panel.rs` | Свойства |
| `crates/bluelink_ui/src/media.rs` | Embeds картинок |
| `crates/bluelink_core` (парсер preview / wikilinks) | Синтаксис Markdown / wiki |

### Общие правила реализации

1. Источник истины — текст заметки на диске (Obsidian-совместимый Markdown). UI-состояние (сессионные складки) не должно ломать файл без явной семантики в тексте (как `+`/`-` у callout).
2. Каждая команда из меню Obsidian получает тот же смысл, даже если shortcut другой.
3. После этапа: `cargo test -p bluelink_ui` (и `-p bluelink_core`, если трогали парсер) + ручная проверка из чеклиста этапа.
4. Не раздувать этап «заодно Prism / Vim / multi-cursor» — это бэклог в конце.

### Статус на момент составления плана

Пункт 1 (сворачивание) уже в работе: есть `fold.rs`, меню Fold/Unfold/Fold all/Unfold all, маркеры callout `+`/`-` в `preview.rs`. Этапы 1.x — **довести и зафиксировать**, а не начинать с нуля.

## Этап 1 — Сворачивание (fold)

Цель этапа-группы: поведение как у `editor:fold-more|less|all|unfold-all` для заголовков, вложенных списков и callout.

### 1.1 Зафиксировать модель регионов

**Цель.** Явно описать, что сворачивается и где хранится состояние.

**Сделать.**

1. Документировать в комментарии модуля (без отдельного README):  
   - заголовок ATX `#`…`######` → регион до следующего заголовка ≤ уровня;  
   - блок с большим indent → до blank / fence / меньшего indent;  
   - callout → маркер `-`/`+` **в тексте** заметки, не в session-fold.
2. Проверить `fold::regions` на fence: строки внутри ` ``` ` не дают ложных heading/indent-регионов.
3. Unit-тесты в `fold.rs`: один документ с H1/H2, вложенный список, callout-заголовок (callout не в session-regions).

**Критерий готовности.** Тесты зелёные; ручная заметка с тремя видами блоков не путает границы.

### 1.2 Скрытие строк в live-редакторе

**Цель.** Закрытый регион не рисует тело; заголовок остаётся.

**Сделать.**

1. Убедиться, что `editor.rs` применяет `fold::hidden` до layout высоты и hit-test.
2. Стрелки Up/Down и клик по outline перескакивают скрытые строки (`step_visible` / `unfold_containing`).
3. При правке текста выше складки — `shift_lines`; после reload — `retain_valid`.

**Критерий готовности.** Свернуть H2 → тело пропало; правка H1 выше не «ломает» индекс складки; переход из outline к строке внутри складки раскрывает её.

### 1.3 UI-аффорданс на строке

**Цель.** Пользователь видит и кликает fold без меню.

**Сделать.**

1. Шеверон/каретка слева у заголовка и у корня indent-блока (как у Fold в меню).
2. Клик по шеврону = toggle `closed` для `region.start`.
3. Для callout: клик по маркеру/шеврону на карточке вызывает `set_callout_collapsed` (уже есть заготовки в `preview.rs`).

**Критерий готовности.** Мышью можно сложить/разложить без открытия меню.

### 1.4 Команды меню и hotkeys

**Цель.** Паритет команд Obsidian.

**Сделать.**

1. Проверить `EditorAction::{FoldMore,FoldLess,FoldAll,UnfoldAll}` в `editor_menu.rs` и обработку в `editor.rs`.
2. `Fold more` = закрыть самый внутренний открытый регион под кареткой (callout text-marker предпочтительнее session-fold, если оба кандидаты).
3. `Fold less` = открыть самый внутренний закрытый.
4. `Fold all` / `Unfold all` = все session-регионы + все callout-маркеры (`set_all_callouts_collapsed`).
5. Опционально: привязать те же хоткеи, что в Obsidian (если уже есть keymap-слой — добавить туда; иначе только меню).

**Критерий готовности.** Четыре пункта меню Fold меняют видимость так же, как ожидается по именам команд.

### 1.5 Регрессия и polish сворачивания

**Цель.** Закрыть дыры перед переходом дальше.

**Сделать.**

1. Сценарий: складка + вставка/удаление строк внутри и снаружи.
2. Сценарий: складка + find/replace, попадающий в скрытое тело (либо раскрыть, либо искать по буферу — выбрать одно поведение и зафиксировать).
3. Убрать дубли/мёртвый код, оставшийся от черновика fold.

**Критерий готовности.** Нет очевидных рассинхронов высоты скролла; пункт 1 из исходного списка можно считать закрытым.

Поиск идёт по всему буферу и раскрывает складку в точке совпадения. Замена сдвигает индексы складок. Undo и redo заметки их сбрасывают.

## Этап 2 — Комментарии `%%`

Цель: `editor:toggle-comments` и live-видимость как в Obsidian (`sandbox/Formatting/Comment.md`).

### 2.1 Парсинг и хранение

**Цель.** Корректно распознавать inline и block `%%…%%`.

**Сделать.**

1. В core/preview: spans для comment (не выкидывать из строки при live-render).
2. Различить: `%% comment %%` в абзаце vs отдельная строка/`%%` block.
3. Unit-тесты на вложенность и незакрытый `%%`.

**Критерий готовности.** Парсер отдаёт comment-span; сырой текст в буфере не меняется от открытия заметки.

### 2.2 Live-отрисовка

**Цель.** В live preview комментарий **виден** (приглушённый стиль), в отличие от текущего «вырезать из превью».

**Сделать.**

1. В `preview.rs` / `render_line_*`: рисовать comment другим цветом/opacity, не удаляя глифы из layout (чтобы курсор совпадал с буфером).
2. Режим чтения (этап 3) позже может скрывать comment — заложить флаг `show_comments`, по умолчанию `true` в live.

**Критерий готовности.** Набрать `Hello %%secret%% world` — все три части на экране; курсор попадает в `secret`.

### 2.3 Команда Toggle comments

**Цель.** Обернуть/снять `%%` у выделения или строки.

**Сделать.**

1. `EditorAction::ToggleComments` + пункт меню.
2. Нет выделения → обернуть текущую строку / снять, если уже comment.
3. Есть выделение → обернуть диапазон; повтор — снять внешние `%%`.

**Критерий готовности.** Меню/команда симметрично включает и выключает comment без порчи соседнего Markdown.

**Критерий готовности.** Можно править YAML+тело одним полем; вернуться в Live — строки снова разобраны.

Цель: подсказки и embeds секций; команды `editor:insert-embed`, `editor:insert-tag`.

### 4.1 Модель фрагментов в подсказке `[[`

**Цель.** После имени файла предлагать `#heading` и `^block`.

**Сделать.**

**Критерий готовности.** Без ручного набора фрагмента можно собрать `[[Note#H2]]` и `[[Note#^id]]`.

### 4.3 Команда Insert embed

**Цель.** `editor:insert-embed` → `![[…]]`.

**Сделать.**

### 4.4 Рендер секционного embed

**Цель.** `![[Note#Heading]]` и `![[Note#^id]]` показывают **фрагмент**, не весь файл.

**Сделать.**

3. Нет цели / нет fragment → явный fallback (пусто / вся заметка / ошибка) — одно поведение, зафиксировать.

**Критерий готовности.** Embed заголовка не тащит соседние секции; block-embed — только блок с `^id`.

### 4.5 Регрессия навигации

**Цель.** Не сломать уже работающие клики по `#` / `^` в обычных (не embed) ссылках.

**Критерий готовности.** Старые переходы зелёные; новые embeds соответствуют срезу.

## Этап 7 — Сноски

Цель: именные, многоабзацные, inline — как `sandbox/Formatting/Footnote.md`.

### 7.1 Именованные маркеры `[^id]`

**Цель.** Не только `[^1]`.

**Сделать.**

1. Расширить `footnote::parse_def` / marker parse: id = `[A-Za-z0-9_-]+` или как в Obsidian sandbox.
2. Live-поле определения работает с string id, не только `u32`.
3. Миграция API: заменить `u32` на `FootnoteId` (enum Number/Name или просто `String`).

**Критерий готовности.** `[^bignote]: …` редактируется и рендерится; старые `[^1]` не сломаны.

### 7.2 Многоабзацные определения

**Цель.** Тело сноски = несколько строк с отступом после `[^id]:`.

**Сделать.**

1. Парсер собирает continuation lines (indent > 0 / правила CommonMark footnote, как в sandbox).
2. UI: многострочное поле или edit source lines as block.
3. Enter внутри определения добавляет абзац в footnote, не «commit и выйти», либо явный modifier — выбрать одно и зафиксировать.

**Критерий готовности.** Два абзаца в определении сохраняются в файле и видны в UI.

### 7.3 Inline-сноски `^[…]`

**Цель.** Поддержка синтаксиса inline footnote.

**Сделать.**

1. Распознать `^[text]` в spans.
2. Рендер: маркер + popover/снизу авто-определение (как в Obsidian reading) — минимальный вариант: показать text в tooltip/снизу без отдельной def-строки.

**Критерий готовности.** Строка с `^[note]` не выглядит как сырой мусор; содержимое доступно читателю.

### 7.4 Навигация маркер ↔ определение

**Цель.** Клик по `[^id]` ведёт к определению и обратно.

**Сделать.**

1. Hit-test на маркере → scroll/focus def.
2. Из def — назад к первому маркеру (если дешево).

**Критерий готовности.** В заметке со сноской внизу переход работает без ручного скролла-угадывания.
